The orchestrator owns startup and teardown. BotManager reserves capacity before asynchronous work; each BotSession owns one identity and lifecycle. An adapter connects a profile with an AbortSignal and normalized lifecycle callbacks. The registry stores validated profiles, not behavior. The bus accepts named envelopes (event ID, timestamp, correlation ID, agent ID, payload) and dispatches through a bounded queue. Repositories own SQL. The AI gateway takes a session snapshot and calls a provider with a bounded prompt; only validated decisions leave the gateway. Decisions are data, never executable instructions.

## Contracts and limits

- `AgentRegistry.register(profile)` validates and copies identity/configuration. `BotManager.start(id)` synchronously reserves a slot and returns a session, **not** a promise of successful spawn. `stop(id)`, `restart(id)` and `close()` await cleanup. Duplicate/reserved, disabled, over-limit and low-memory starts fail admission. Stagger slots are shared across initial connections and retries.
- `connect(config, profile, signal, { login, spawn, update, error, end })` checks authorization, probes the exact TCP endpoint and selects an explicitly tested protocol. `login` enters SPAWNING; `spawn(observations)` enters CONNECTED. `end` terminates an attempt; transport errors and kicks are normalized rather than persisting arbitrary server-provided text.
- `MessageBus.publish(type, agentId, payload, correlationId?, id?)` validates an envelope, returning `false` for duplicates or a full queue. Listeners subscribe to one type or `*`; callbacks may be async. Publication is nonblocking, dispatch is ordered, and each subscriber gets a copy. The last 2,048 accepted IDs are retained. **Not a durable broker**: overload is logged and counted, database consumer failures are isolated, and events are not replayed. Do not depend on this queue for exactly-once delivery.
- State changes and AI results are persisted transactionally with their event. `agent_states` contains the latest *lifecycle snapshot*, not a per-tick movement history. Migrations run under a database lock; MySQL DDL implicitly commits, so initial DDL is restartable with `IF NOT EXISTS` and only completed migrations enter the ledger.
- `LlmGateway.decide(agentId)` reads that agent’s isolated, bounded context. Providers implement `complete(messages, correlationId) -> string`; NIM additionally implements startup discovery. There is one in-flight decision per agent, four globally, a sliding one-minute attempt budget (retries included), and a three-second same-context cache. Only `observe`, `wait` and `explore` are recognized, with at most eight actions. No action executor exists.
- Metrics are read-only on loopback. Latency is the latest decision duration, CPU is cumulative process CPU time, and event-loop delay is a mean. Records are keyed by agent ID and correlation ID, never by a token. Upgrade to a durable outbox and benchmark before making production delivery or capacity guarantees.
